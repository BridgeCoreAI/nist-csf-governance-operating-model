# Operating Model

## The Core Idea

Governance frameworks describe what should happen. Operating models describe how an organization actually knows it happened. This repository is an operating model for the NIST CSF 2.0 GOVERN function: a working example of turning each GOVERN category into control records, evidence, registers, and review cadences that a real team could run.

## The Governance Cycle

Every control in this model moves through the same cycle:

1. **Assess**: evaluate design and operating effectiveness against the control's stated requirements
2. **Evidence**: attach specific, dated evidence supporting the assessment, with stated limitations
3. **Find**: document any gap identified, tied to specific evidence
4. **Recommend**: propose a fix that addresses that exact gap, with an operationalization plan
5. **Track**: assign an owner, a due date, and a completion measure
6. **Review**: revisit on a defined cadence, closing the loop back to Assess

## Why GitHub

GitHub provides version history, pull request review, issue tracking, and scheduled automation, all useful primitives for building traceability and accountability into a governance process. This repository uses GitHub as the substrate for that structure. It does not claim GitHub itself constitutes compliance. See `limitations.md`.

## Scope of the Current Release

This release operationalizes GV.OC (Organizational Context) only. The same operating model applies to every future GOVERN category; only the specific controls and registers differ.
